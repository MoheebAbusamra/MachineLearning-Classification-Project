The problem: an insurance company wants to know, before it happens, which customers are likely to file a claim. The target is CLAIM_FLAG (1 = claimed, 0 = no claim). The inputs are the customer's demographics (age, kids, marital status), finances (income, home value), car (type, value, age, use) and driving history (past claims, traffic points, revoked licence).

The story in one paragraph: we audited and cleaned the data (removed a column that leaked the answer, fixed currency stored as text, set impossible values to missing), explored it with six figures, built one preprocessing pipeline, trained 5 models plus a Dummy baseline with 5-fold cross-validation, selected features with filters, wrappers and L1, tuned hyperparameters with grid search, lowered the decision threshold because missing a claimant is costly, and only then tested once on the held-out 20%. Gradient Boosting won (ROC-AUC 0.832, F1 0.621, recall 0.778). Learning curves and the bias-variance decomposition show the remaining limit is bias: the features themselves carry limited signal.

Raw CSV→Audit→Clean→EDA→Split 80/20→Pipeline→Baselines (CV)→Feature selection→Tuning + threshold→Test once→Diagnose

1. Setup and MLflow

What we did: imported the libraries, fixed the random seed (RANDOM_STATE = 42), created the MLflow experiment "Car Insurance Claim - Classification" in a local ./mlruns folder, and loaded the CSV into df_raw.

Why: the seed makes every random step (split, folds, trees) repeat exactly, so results are reproducible. MLflow is required by the module: every experiment, its settings, scores and plots are recorded so they can be compared later.

If asked "why n_jobs=1?": running in parallel on Windows printed pickling errors, so everything runs on one core. It only affects speed, not results.

3. Data Cleaning

What we did, in order, on a copy df (the original stays as df_raw):

  • Removed the 1 exact duplicate row (10,302 → 10,301).
  • Converted the 5 currency columns to numbers with a regex helper parse_money (removes $ and ,).
  • Removed the export leftover z_ prefix from labels (z_No → No) and shortened long labels ("Highly Urban/ Urban" → "Urban").
  • Checked whether BIRTH could fill the 7 missing ages: it gives ages 11 to 15, below driving age, so it is unreliable. BIRTH matches AGE in 99.88% of rows, so it was dropped as redundant.
  • Set impossible values to missing: 1 negative CAR_AGE, 13 YOJ values meaning the job started before age 10.
  • Consistency checks passed: OLDCLAIM > 0 exactly when CLM_FREQ > 0; every single parent has children at home.
  • Dropped ID, BIRTH, CLM_AMT, leaving 23 features. Assigned each to a group: 13 numeric, 7 binary, 1 ordinal, 2 nominal.
Why impossible values become NaN instead of being deleted: the rest of the row is still good data. Setting one cell to missing lets the pipeline impute it, and we keep the customer.

Careful with the bias-variance numbers: they use 0-1 loss at the model's default cut-off, and models trained with class_weight="balanced" (SVM, DT) predict "claim" more often, which raises 0-1 loss even when their ranking is good. That is why SVM has high loss but good ROC-AUC. Use these numbers to compare bias versus variance within a model, not to rank models.

Concepts: data and preprocessing

Supervised classification

Learning from labelled examples (customers whose outcome we know) to predict a category for new examples. Here binary: claim or no claim.

Class imbalance

When one class is much more common (73% vs 27%). Models drift towards predicting the majority. Fixes we used: stratification, metrics that care about the minority (F1, recall, ROC-AUC), class_weight="balanced", and a lower decision threshold.

Data leakage

When the model sees information during training that it would not have at prediction time, giving fake high scores. Two types here: target leakage (CLM_AMT is only known after a claim) and train-test leakage (learning imputation medians or scaling means from data that includes the validation or test rows). We avoided both: dropped CLM_AMT, and put preprocessing inside the pipeline so it is fitted on training folds only.

Train/test split and stratification

We hold back 20% as a test set that plays the role of "future customers". Stratified means both parts keep the same class ratio (26.7% claims), so the test score is not distorted by an unlucky split.

Imputation (median, most frequent, constant)

Filling missing values. Median for numbers because it ignores extreme values. Most frequent for binary/ordinal categories. Constant "Unknown" for nominal OCCUPATION, so missing rows are not wrongly merged into the largest (and high-risk) group.

Encoding: one-hot vs ordinal

Models need numbers. One-hot creates one 0/1 column per category, used when there is no order (car type). Ordinal maps categories to ordered numbers (High School < Bachelors < PhD), used when order matters. drop="if_binary" keeps one column for yes/no features because the second column would be redundant.

Scaling (StandardScaler) and fit vs transform

Rescales each numeric column to mean 0 and standard deviation 1, so income (tens of thousands) does not dominate kids (0 to 5). Needed by distance-based (KNN, SVM) and gradient-based (LR) models; trees do not care. fit learns the mean and std from training data; transform applies them. Test data is only transformed, never fitted, to prevent leakage.

Pipeline and ColumnTransformer

ColumnTransformer sends each column group to its own steps. Pipeline chains preprocessing and model into one object, so fit and predict run all steps in the right order. Inside cross-validation, the whole pipeline is re-fitted on each training fold, which is what prevents leakage.

Outliers and the IQR rule

IQR = Q3 - Q1. Values below Q1 - 1.5×IQR or above Q3 + 1.5×IQR are flagged. Flagged does not mean wrong: here they were real customers (e.g. people with past claims), so we kept them.

Skewness

How lopsided a distribution is. Positive skew: a long tail to the right (most people have 0 past claims, a few have very large ones). It motivated median imputation, scaling and Spearman correlation.

Concepts: evaluation and metrics

All metrics use these four counts. Example: Gradient Boosting on the test set.

TermMeaningGB value

Accuracy

(TP + TN) / all. Share of correct predictions. Misleading with imbalance: the Dummy gets 73.4% while catching nobody.

Precision

TP / (TP + FP) = 427 / 827 = 0.516. "When the model says claim, how often is it right?" Low precision means many false alarms.

Recall (sensitivity)

TP / (TP + FN) = 427 / 549 = 0.778. "Of all real claimants, how many did we catch?" The metric that cares about missed claims.

F1 score

Harmonic mean of precision and recall: 2PR / (P + R) = 0.621 for GB. High only when both are reasonable. Used as the secondary metric and as the objective for the threshold.

ROC curve and ROC-AUC

The ROC curve plots recall (true positive rate) against false positive rate for every possible threshold. AUC is the area under it: the probability that a random claimant gets a higher risk score than a random non-claimant. 0.5 = random guessing, 1.0 = perfect. It does not depend on the threshold or on class balance, which is why it was the main metric for comparing and tuning models.

Precision-recall curve and average precision

Precision against recall for every threshold. More informative than ROC when the positive class is rare. Average precision summarises it in one number (GB 0.66). A random model would score about 0.27 (the claim rate).

Classification report, macro vs weighted average

Precision, recall, F1 and support for each class. Macro averages the two classes equally (fair to the minority). Weighted averages by class size (dominated by "no claim").

Decision threshold

A model gives a score; it predicts "claim" if the score is above the threshold (default 0.5 for probabilities). Lowering it catches more claimants (higher recall) at the cost of more false alarms (lower precision). ROC-AUC is unchanged because the ranking is unchanged; only precision, recall, F1 and accuracy move.

Cross-validation (StratifiedKFold, 5 folds)

Split the training set into 5 parts keeping the class ratio. Train on 4, validate on 1, rotate 5 times, average. Gives a more reliable score than one validation split and uses all training data. The same cv object is used everywhere so all models see identical folds (a fair comparison).

Why the test set is used only once

Every decision made by looking at a score "leaks" a little information. If we tuned on the test set, it would no longer be unseen. CV made all choices; the test set only confirms them.

Dummy baseline

DummyClassifier(strategy="most_frequent") always predicts "no claim". Any useful model must beat it on the metrics that matter.

Concepts: the 5 models and their hyperparameters

Parameter vs hyperparameter: parameters are learned from data during training (LR weights, tree split points). Hyperparameters are settings we choose before training that control how the model learns (C, depth, k). We choose them with validation curves and grid search.

LinearLogistic Regression

Idea: a weighted sum of the features passed through a sigmoid to give a probability of claim. Each weight shows how a feature pushes the risk up or down, so it is easy to explain.

  • C: inverse of regularisation strength. Small C = strong penalty on large weights = simpler model (can underfit, as at C = 0.0001). Large C = weak penalty (can overfit). Best: 1.
  • l1_ratio (penalty type): 0 = L2 (ridge), shrinks all weights a little. 1 = L1 (lasso), can push weights to exactly 0, which is feature selection. Best: L1.
  • class_weight: None or "balanced" (makes mistakes on the rare class cost more). Best: None, the threshold handles imbalance instead.
  • solver="saga": an optimiser that supports both L1 and L2.

Instance-basedK-Nearest Neighbours (KNN)

Idea: no real training. To predict a customer, find the k most similar customers (by distance on scaled features) and let them vote.

  • n_neighbors (k): small k follows individual points (high variance, k = 1 memorises). Large k smooths the decision (more bias). Best: 75.
  • weights: "uniform" (every neighbour equal) or "distance" (closer neighbours count more). Best: distance.

Why training F1 = 1.0: with distance weighting, a training point is its own nearest neighbour at distance 0, and a zero-distance neighbour gets all the weight, so it always predicts its own label. This is not a bug; it is why the training score is not meaningful for KNN. The validation score is what counts.

Why it needs feature selection most: every feature enters the distance, so useless features add noise for all customers (the "curse of dimensionality").

KernelSupport Vector Machine (SVM, RBF kernel)

Idea: find the boundary that separates the classes with the widest possible margin. The RBF kernel lets the boundary be curved by measuring similarity between customers.

  • C: penalty for points on the wrong side of the margin. Large C = tries to classify every training point correctly (narrow margin, overfit risk). Small C = wider, smoother margin. Best: 1.
  • gamma: how far the influence of one training point reaches. Large gamma = very local, wiggly boundary (overfit). Small gamma = smooth boundary. Best: 0.01.
  • class_weight: Best: balanced.

Slowest model to train (about O(n²)), which is why its grid was kept small (8 combinations).

TreeDecision Tree

Idea: a flowchart of yes/no questions ("urban?", "past claims > 0?") learned by picking the split that best separates the classes at each step. Very interpretable, but unstable.

  • max_depth: maximum number of questions in a path. Too deep = memorises (baseline gap 0.562). Best: 10.
  • min_samples_leaf: the minimum number of customers in a final leaf. Larger = smoother, avoids rules based on a handful of people. Best: 50.
  • ccp_alpha: cost-complexity pruning. After growing, branches whose improvement is smaller than alpha are cut back. Best: 0.0005.
  • class_weight: Best: balanced.

EnsembleGradient Boosting

Idea: build many small trees one after another; each new tree corrects the errors the previous trees still make. The final prediction adds them all up. Boosting mainly reduces bias.

  • n_estimators: number of trees. More trees = more corrections (too many can overfit). Best: 300.
  • learning_rate: how much each tree is allowed to correct. Smaller = slower, more careful learning, usually needs more trees. Best: 0.05.
  • max_depth: size of each tree. Depth 2 means each tree can capture interactions between 2 features. Best: 2.
  • subsample=0.8 (fixed): each tree sees a random 80% of rows, which adds randomness and lowers variance (stochastic gradient boosting).

Tuning tools

GridSearchCV

Tries every combination in the grid with 5-fold CV and keeps the best by ROC-AUC (refit="roc_auc"), then retrains it on the full training set. Exhaustive and simple; cost grows with the grid size (DT grid = 4 × 3 × 3 × 2 = 72).

Validation curve

Training and validation score while one hyperparameter changes. Where they split apart is overfitting; where both are low is underfitting. We used it to pick sensible grid ranges.

class_weight="balanced"

Weights each class inversely to its frequency, so a mistake on a claimant costs about 2.75 times a mistake on a non-claimant during training.

TunedThresholdClassifierCV

Wraps a tuned model and searches, with cross-validation on the training set, for the threshold that maximises F1. The test set is not used.

Concepts: bias, variance and the curves

Bias (underfitting)

Error from a model that is too simple to capture the pattern. It is wrong in the same way no matter which training data it sees. Signs: training and validation scores both low and close together. Example: Logistic Regression (gap 0.005, flat at 0.810).

Variance (overfitting)

Error from a model that is too sensitive to the specific training data. It learns noise, so it changes a lot when the data changes. Signs: training score much higher than validation. Example: the unpruned Decision Tree (gap 0.562), and the tuned tree still has the highest variance (0.176).

The bias-variance trade-off

Making a model more flexible (deeper tree, smaller k, larger C or gamma) lowers bias but raises variance. Regularisation (pruning, larger k, smaller C, L1/L2) does the opposite. Tuning searches for the sweet spot. Total error ≈ bias + variance + noise that no model can remove.

Learning curve

Training and validation score as the training set grows. If the validation curve is still rising, more data would help (variance problem). If both curves have met and gone flat, more data will not help (bias problem); you need a more flexible model or better features.

Bias-variance decomposition (mlxtend)

Trains the model 20 times on bootstrap samples of the training set and predicts the test set each time. Bias = how often the most common prediction is wrong. Variance = how often individual predictions disagree with the most common one. Uses 0-1 loss.

Overfitting check (train vs validation gap)

From cross_validate(..., return_train_score=True). A large gap means the model scores well on data it has seen and worse on new data.

Likely questions and short answers

Why is ROC-AUC your main metric and not accuracy?

Accuracy rewards predicting the majority: the Dummy scores 73.4% and catches no claimant. ROC-AUC measures how well the model ranks claimants above non-claimants, independent of the threshold and class balance. F1 is reported alongside because it reflects the chosen threshold.

Why did you drop CLM_AMT?

It is target leakage: CLM_AMT > 0 exactly when CLAIM_FLAG = 1, and the amount only exists after a claim. Keeping it would give a near-perfect but useless model.

How did you prevent data leakage in preprocessing?

Preprocessing is inside the pipeline, so during CV the imputer and scaler are fitted on the 4 training folds only. The test set is only transformed with values learned from training data and was used once at the end.

Why impute instead of dropping missing rows?

Only 1.08% of cells are missing, but they are spread over 25.67% of rows. Dropping would lose a quarter of the data. Missingness is not related to the target, so imputation is safe.

Why "Unknown" for OCCUPATION but most frequent for other categories?

The most frequent occupation is Blue Collar, a high-risk group (35.1%). Missing-occupation rows claim at 26.2%, close to average, so forcing them into Blue Collar would distort that group.

Why are the zeros real values and not missing?

The dataset already uses NaN for unknowns in the same columns. Zero income goes with zero years-on-job (students, home makers), zero home value with renters, and zero past claims match in both claim columns. Zero-income customers claim 40% vs 25.6%, so the zeros carry signal.

Why did you keep the outliers?

They are real customers (people with kids, past claims, high income), not errors. The IQR rule flags them because those columns are mostly zeros. Removing them would remove high-risk customers.

Why does Logistic Regression do almost as well as Gradient Boosting?

Most of the signal is additive: each risk factor pushes the risk up or down on its own. Gradient Boosting adds a little by capturing interactions (depth-2 trees), +0.02 ROC-AUC on test.

Why did the Decision Tree gain the most from tuning?

By default it grows until it memorises the training data (gap 0.562). Limiting depth, leaf size and pruning removed most of that overfitting: +0.156 ROC-AUC.

KNN has training F1 of 1.0. Is it overfitting?

Not in the usual sense. With distance weighting, each training point is its own neighbour at distance 0 and decides its own label. It is a property of the weighting, so we judge KNN on validation and test scores only.

Why lower the threshold? Isn't that cheating?

No. The threshold was chosen with CV on the training set only, by maximising F1. For an insurer a missed claimant costs more than a false alarm, so trading some precision for recall is a business decision. ROC-AUC does not change.

Why use different feature sets for KNN?

Each model was scored on each set with the same CV. KNN gained +0.021 with the 17 SFS features because irrelevant features add noise to distances. The other models were equal or better with the 21-feature filter set.

SFS and SBS gave the same answer. What does that tell you?

Two searches from opposite directions reaching the same 17 features is strong evidence that the 6 dropped features are not needed by a linear model.

Is your best model overfitting?

No. Train-validation gap 0.025, test ROC-AUC (0.832) close to CV (0.826), and low variance (0.035) in the decomposition.

How would you improve the results?

The learning curves are flat, so more customers will not help much. The limit is bias from the features: better features (mileage, telematics, claim history detail) would help more than more rows or a more complex model.

Why Spearman correlation?

Many features are skewed with outliers. Spearman uses ranks, so it is robust to both and captures any monotonic relationship, not only straight lines.

Why stratify the split and the folds?

To keep the 26.7% claim rate in every part. Otherwise one fold could get more or fewer claimants by chance, making scores noisy and unfair between models.

What does the red car result show?

Red and non-red cars have the same claim rate (26.2% vs 26.9%), mutual information is 0, and SFS/SBS drop it. The common belief is not supported by this data.

Which features drive the risk?

Urban living (LR weight +2.46), revoked licence (+0.90), single parent (+0.41), sports car, past claims and traffic points raise risk. Manager occupation, private car use, minivan and being married lower it.
